# LotCP — lot-exchangeable few-shot conformal calibration for NIR fruit-quality predictions

Code, stored predictions, results and manuscript sources for the study

> *How many reference fruit does a valid error bar need? Lot-exchangeable few-shot conformal
> calibration of near-infrared dry-matter predictions across harvest seasons.*

The study asks whether prediction intervals for mango dry-matter content (DMC), produced by a
near-infrared (NIR) calibration trained on past harvest seasons, keep their nominal coverage on the
harvest lots of a later season, and how a few destructively measured reference fruit per lot can
be used to obtain valid and narrow intervals.

Everything reported in the manuscript is generated by this repository. No number in a table or in
the text is typed by hand: the manuscript builder fills placeholders from `results/` and `tables/`.

## 1. Install

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt            # requirements-lock.txt has the exact versions used
```

or `conda env create -f environment.yml`. Python 3.11+ (3.13 was used). No GPU is needed; the code
picks CUDA, Apple-silicon MPS or CPU automatically (`src/utils.py:get_device`). Building the
manuscript additionally needs `pandoc` and, for the PDF, LibreOffice.

## 2. Data

The data set is public: *Mango DMC and NIR spectra*, Mendeley Data,
doi:[10.17632/46htwnp833](https://doi.org/10.17632/46htwnp833) version 6, file
`MangoDMC_NIR_Data_v4.csv` (260 MB, CC BY 4.0). It is **not** redistributed here.

```bash
python -m src.data.download        # downloads to data/raw/ and verifies the SHA-256 checksum
```

If the provider releases a newer version the checksum test fails on purpose; the URL and checksum
are in `config/default.yaml`.

## 3. Run

```bash
python run_all.py --mode quick     # ~10 min: reduced computation, checks that every stage runs
python run_all.py --mode full      # the reported experiment
pytest -q                          # unit tests, incl. a Monte-Carlo check of the coverage guarantee
```

Quick mode writes to `quick_outputs/` and never touches the reported results.

Full mode runs eight stages. Each is idempotent and can be started from with `--from <stage>`:

| Stage | Module | What it does | Time (4-core CPU) |
|---|---|---|---|
| `crossfit` | `src/training/crossfit.py` | fits PLS, LightGBM (3 seeds), 1D-CNN (3 seeds) for each target season; stores target predictions and out-of-fold source predictions under sample-, lot- and season-grouped folds | ~2 h (CNN) |
| `extra` | `experiments/extra_runs.py` | PLS cross-fits for the extra shift protocols (recent seasons, region, cultivar) | ~5 min |
| `uq` | `src/training/uq_models.py` | conformalised quantile regression, quantile regression forest, deep ensemble, MC dropout | ~25 min |
| `eval` | `src/evaluation/run_eval.py` | all interval methods on all target lots, 100 reference draws per lot and m | ~30 min |
| `robustness` | `experiments/robustness.py` | reference noise, outlier screening, number of past lots, tuning constants, other shifts, subgroup/error analysis, cost | ~15 min |
| `analysis` | `src/statistics/analysis.py` | bootstrap CIs, paired Wilcoxon tests with Holm correction, all tables | ~1 min |
| `figures` | `src/visualization/figures.py` | all figures (PNG + PDF) | ~1 min |
| `manuscript` | `manuscript/build_manuscript.py` | Markdown → DOCX → PDF with numbers filled from result files | ~1 min |

### Reproducing the manuscript numbers without retraining

The cross-fitted predictions of every model are stored in `results/predictions/` (float32). With
the data file in place,

```bash
python run_all.py --mode full --from eval
```

recomputes every interval result, statistic, table, figure and the manuscript from those
predictions in about 45 minutes. Reference draws and episodes are seeded
(`config/default.yaml: eval.seed`), so the numbers are reproduced exactly. Retraining from scratch
(`--from crossfit` after deleting `results/predictions/`) reproduces PLS and LightGBM exactly and
the CNN up to floating-point differences between machines.

## 5. The method in one paragraph

Scans are nested in reference samples, samples in harvest lots, lots in seasons. For every source
season the predictor is refitted without that season, giving *season-held-out residuals* for all
past lots. For a new lot with `m` reference samples, LotCP (i) shrinks the mean reference residual
towards the past mean to estimate the lot bias, (ii) optionally (LotCP-S) estimates a lot scale
from the variance of the reference residuals and from the label-free variance of repeated-scan
predictions, and (iii) takes as half-width the lot-balanced conformal quantile of the scores
obtained by replaying exactly this `m`-shot procedure on every past lot. See
`src/evaluation/lotcp.py`; the class is ~150 lines and has no dependency beyond NumPy.

```python
from src.evaluation.lotcp import LotCP
cp = LotCP(m=10, alpha=0.1, scale="full").fit(residuals, lot_ids, sample_ids, predictions)
bias, half_width = cp.predict(reference_sample_mean_residuals, replicate_variance_of_new_lot)
# interval for a scan x of the new lot:  f(x) + bias ± half_width
```

## 6. Leakage safeguards

* forward chaining: only seasons before the target season are used for training, model selection
  and calibration (`tests/test_splits.py`);
* repeated scans of a sample never straddle a fold; lots and seasons likewise in their schemes;
* reference draws are made per sample and all scans of drawn samples leave the evaluation set;
* preprocessing is row-wise; network scaling constants come from the training fold;
* the protocol was committed before any model was trained (`git log experiments/PROTOCOL.md`).
